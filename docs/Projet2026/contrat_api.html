1. Philosophie du Contrat d’Interface

En ingénierie logicielle comme dans les bibliothèques scientifiques modernes (telles que scikit-learn, SciPy ou PyTorch), une spécification stricte de l’API publique n’est pas un carcan : c’est la garantie fondamentale d’interopérabilité, de testabilité et de modularité.

Ce qui est contractel vs Ce qui est libre

  • Contractuel (Sanctuarisé) : Les noms de modules, noms de classes, signatures de fonctions, propriétés d’accès (@property), exceptions levées et clés de dictionnaires documentés ci-dessous. Les bancs de tests automatisés (CI GitHub Actions et tests d’évaluation) reposent exclusivement sur ces interfaces.

  • Libre (Votre valeur ajoutée) : L’algorithmique interne, le découpage en fonctions auxiliaires privées (_nom_methode), la gestion fine du cache, le choix des bibliothèques de calcul parallèle (joblib ou multiprocessing), l’architecture de vos extensions et l’ensemble de votre tableau de bord Streamlit.

2. Module des Exceptions : pyarena.core.exceptions

Toutes les exceptions métier de l’application dérivent d’une classe racine unique.

class PyArenaException(Exception):
    """Exception racine du projet PyArena."""
    pass

class FighterFaintedError(PyArenaException):
    """Levée lorsqu'une entité K.-O. *hp == 0) tente d'agir ou de subir une action invalide."""
    pass

class InvalidStatError(PyArenaException):
    """Levée lorsqu'une statistique de base ou recalculée est strictement négative ou incohérente."""
    pass

class DataFetchError(PyArenaException):
    """Levée si l'API distante est injoignable ET qu'aucun cache local n'existe sur le disque."""
    pass

3. Modèles de Données : pyarena.core.models

3.1 Classe Abstraite BaseFighter

Classe de base non instanciable (abc.ABC) formalisant le contrat comportemental d’un combattant.

from abc import ABC, abstractmethod

class BaseFighter(ABC):
    @property
    @abstractmethod
    def id(self) -> int:
        """Identifiant numérique officiel PokéAPI."""
        pass

    @property
    @abstractmethod
    def name(self) -> str:
        """Nom du combattant."""
        pass

    @property
    @abstractmethod
    def hp(self) -> int:
        """Points de vie courants."""
        pass

    @hp.setter
    @abstractmethod
    def hp(self, value: int) -> None:
        """Fixe les points de vie avec bornage strict [0, max_hp]."""
        pass

    @property
    @abstractmethod
    def max_hp(self) -> int:
        """Points de vie maximaux calculés au niveau 50."""
        pass

    @property
    @abstractmethod
    def attack(self) -> int:
        """Statistique d'attaque effective."""
        pass

    @property
    @abstractmethod
    def defense(self) -> int:
        """Statistique de défense effective."""
        pass

    @property
    @abstractmethod
    def speed(self) -> int:
        """Statistique de vitesse effective."""
        pass

    @property
    @abstractmethod
    def type_1(self) -> str:
        """Type élémentaire principal (ex: 'Feu', 'Eau', 'Plante', etc.)."""
        pass

    @property
    @abstractmethod
    def type_2(self) -> str | None:
        """Second type élémentaire éventuel, ou None si mono-type."""
        pass

    @abstractmethod
    def take_damage(self, amount: int) -> None:
        """
        Décrémente les points de vie de la valeur indiquée.
        Ne peut jamais laisser hp sous 0.
        Lève FighterFaintedError si le combattant est déjà K.-O. *hp == 0) avant l'appel.
        """
        pass

    @abstractmethod
    def is_alive(self) -> bool:
        """Retourne True si hp > 0, False sinon."""
        pass

    @abstractmethod
    def reset_stats(self) -> None:
        """Restaure les points de vie à leur valeur maximale (hp = max_hp)."""
        pass

7. Vos Degrés de Liberté

Ces mesures n’imposent jamais le déroulement ligne à ligne de vos algorithmes. Chaque equipe conserve une liberté architecturale totale sur :

  1. L’implémentation de la boucle d’affrontement : La manière dont vous séparez les phases de dêgâts, l’aléa ou les affichages texte dans engine.py.
  2. Le partitionnement parallèle : Utilisation de joblib.Parallel avec delayed ou de multiprocessing.Pool.map_async, gestion des graines pour chaque worker (numpy.random.SeedSequence).
  3. La conception de vos extensions (1 à 10) : Vous êtes libres de créer les sous-classes, décorateurs ou modules auxiliaires sous src/pyarena/extensions/ que vous jugez les plus élégants.
  4. l’expérience utilisateur du Dashboard Streamlit : Choix des composants graphiques, organisation spatiale des graphiques Plotly, pop-ups Folium et mise en cache avec @st.cache_data.
