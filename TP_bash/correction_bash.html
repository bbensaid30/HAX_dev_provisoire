1 Guide Général de l’Enseignant

Ce document rassemble la correction intégrale, les sorties textuelles attendues ainsi que les explications techniques associées à chaque question du TP 1.

1.0.1 Objectifs pédagogiques de la séance

  • Casser la peur du terminal en installant des réflexes mécaniques d’auto-complétion (Tab) et de gestion des processus (Ctrl+C).
  • Démystifier la notion d’arborescence : passage maîtrisé des chemins relatifs aux chemins absolus.
  • Comprendre le modèle de sécurité Unix (triplet utilisateur / groupe / autres en lecture, écriture, exécution).
  • Maîtriser le paradigme de composition Unix : canaliser la sortie d’un outil simple pour alimenter le suivant via un tube (|).

2 Exercice 1 : Gymnastique de Navigation & Arborescence

Cet exercice se déroule directement dans l’environnement local de la machine étudiante, avant toute décompression d’archive.

2.0.1 Question 1 : Emplacement initial

pwd
  • Sortie type : /home/etudiant (ou /Users/nom sous macOS).
  • Point pédagogique : Montrer que le terminal démarre par défaut dans le répertoire personnel de l’utilisateur, abrégé par le tilde ~.

2.0.2 Question 2 : Navigation vers la racine absolue

cd /
pwd
ls -l

  • Sortie type de pwd : /

  • Sortie de ls -l :

    drwxr-xr-x   2 root root  4096 août 28 14:02 bin
drwxr-xr-x 130 root root 12288 sept  8 09:15 etc
drwxr-xr-x   3 root root  4096 sept  2 10:00 home
drwxr-xr-x  14 root root  4096 août 12 11:22 var

  • Piège fréquent : Confondre la racine / (root directory) avec le dossier personnel de l’administrateur /root. Expliquer que / est le socle absolu de tout le système de fichiers.

2.0.3 Question 3 : Entrée en chemin relatif dans etc/

cd etc
pwd
  • Sortie attendue : /etc
  • Point pédagogique : Faire remarquer l’absence de slash initial. cd etc signifie « descendre dans le dossier etc qui se trouve là où je suis ». Si l’étudiant tape cd /etc, il utilise un chemin absolu (le résultat est le même ici car on part de /, mais la mécanique conceptuelle est différente).

2.0.4 Question 4 : Remonter d’un cran dans l’arborescence

cd ..
pwd
  • Sortie attendue : /
  • Explication : Le pseudo-répertoire .. pointe systématiquement vers le répertoire parent direct. Tenter de faire cd .. depuis / n’a aucun effet (la racine est son propre parent).

2.0.5 Question 5 : Retourner au répertoire personnel en 2 caractères

cd
# ou bien :
cd ~
  • Vérification : pwd renvoie à nouveau /home/etudiant.
  • Point pédagogique : La commande cd invoquée sans aucun argument ramène automatiquement à la maison ($HOME).

2.0.6 Question 6 : Révéler les fichiers cachés

ls -a
# ou avec détails :
ls -la

  • Sortie type :

    .   ..   .bash_history   .bashrc   .profile   .gitconfig   Documents   Downloads

  • Explication : Sous Linux, un fichier est rendu « caché » par convention dès lors que son nom commence par un point .. Ce ne sont pas des fichiers cryptés : ce sont simplement des fichiers de configuration logicielle masqués pour ne pas encombrer l’affichage quotidien.

3 Préparation : Décompression de l’Archive de Travail

tar -xzvf tp1_linux.tar.gz
cd tp1_linux
pwd
  • Décryptage des options de tar :
    • -x : extract (extraire les fichiers de l’archive).
    • -z : gzip (décompresser le flux compressé avec l’algorithme gzip).
    • -v : verbose (lister à l’écran les fichiers au fur et à mesure de l’extraction).
    • -f : file (spécifier le nom du fichier archive cible — cette option doit toujours être placée immédiatement avant le nom de l’archive).

4 Exercice 2 : Manipulation de Fichiers & Jokers (Wildcards)

Positionnement initial :

cd exercice_1
ls -l vrac/

4.0.1 Question 1 : Déplacer tous les fichiers .png en une seule commande

mv vrac/*.png documents/images/
  • Mécanisme sous-jacent (Globbing) : Ce n’est pas la commande mv qui comprend le caractère *. C’est l’interpréteur Bash qui, avant d’exécuter la commande, remplace vrac/*.png par la liste explicite vrac/figure_test.png vrac/photo_01.png vrac/photo_02.png vrac/photo_03.png.
  • Vérification : ls documents/images/ doit afficher les 4 images.

4.0.2 Question 2 : Déplacer tous les fichiers .txt

mv vrac/*.txt documents/textes/
  • Vérification : ls documents/textes/ doit afficher notes.txt et rapport.txt.

4.0.3 Question 3 : Création du dossier code/

mkdir code
  • Erreur fréquente : Taper mkdir /code. Cela tente de créer un dossier à la racine absolue du système, ce qui échouera immédiatement par un message Permission denied. Rappeler l’importance de l’absence de / pour travailler dans le dossier courant.

4.0.4 Question 4 : Copie de script.py vers code/

cp vrac/script.py code/
  • Point pédagogique : Bien insister sur la différence sémantique : cp duplique les octets sur le disque (le fichier source existe toujours dans vrac/), alors que mv déplace le pointeur d’indexation sans dupliquer la donnée.

4.0.5 Question 5 : Suppression du dossier vrac/

rm -r vrac/
  • Explication de l’option -r : Par défaut, la commande rm refuse de supprimer un dossier pour éviter les désastres accidentels (rm: cannot remove 'vrac/': Is a directory). L’option récursive -r ordonne la suppression de tous les fichiers contenus à l’intérieur puis du dossier lui-même.
  • Avertissement de sécurité : Rappeler qu’il n’existe aucune commande undo ni aucune corbeille sous Linux. Tout ce qui est supprimé par rm est définitivement rayé du système de fichiers.

5 Exercice 3 : Droits d’Accès et Permissions Linux

Positionnement initial :

cd ../exercice_2
ls -l scripts/

5.0.1 Question 1 & 2 : Constat du blocage d’exécution

./scripts/backup.sh
  • Message renvoyé : bash: ./scripts/backup.sh: Permission denied
  • Explication : En tapant ls -l scripts/backup.sh, on observe les droits : -rw-r--r-- 1 etudiant etudiant 215 sept 10 08:00 scripts/backup.sh Bien que l’utilisateur soit le propriétaire légitime du fichier, le bit d’exécution x est absent. Sous Unix, l’extension .sh ou .exe n’accorde aucun privilège : seul l’état des bits de permissions détermine si un fichier a le droit d’être chargé en mémoire comme un programme exécutable.

5.0.2 Question 3 : Rendre le script exécutable et le lancer

chmod +x scripts/backup.sh
# Variante stricte pour le propriétaire seul :
# chmod u+x scripts/backup.sh

./scripts/backup.sh

  • Sortie affichée dans le terminal :

    =========================================================
[SUCCÈS] Le script de sauvegarde s'est exécuté sans erreur !
Tous les instantanés système ont été synchronisés.
=========================================================

5.0.3 Question 4 & 5 : Sécurisation du fichier d’identifiants secret.conf

État initial : chmod 666 (-rw-rw-rw-). N’importe quel processus de la machine peut lire et écraser les clés secrètes.

Commande de restriction octale attendue :

chmod 600 scripts/secret.conf

  • Vérification obligatoire :

    ls -l scripts/secret.conf

    La sortie doit afficher rigoureusement : -rw------- 1 etudiant etudiant 115 sept 10 08:00 scripts/secret.conf

  • Détail du calcul octal :

    • Utilisateur (Propriétaire) = 6 : Lecture (\(4\)) + Écriture (\(2\)) = \(6\).
    • Groupe = 0 : Aucun droit (\(0\)).
    • Autres = 0 : Aucun droit (\(0\)).

  • Variante symbolique équivalente :

    chmod go-rw scripts/secret.conf

    (retirer la lecture et l’écriture au groupe g et aux autres o).

6 Exercice 4 : Redirections, Filtres et Pipelines (|)

Positionnement initial :

cd ../exercice_3/logs

6.0.1 Question 1 : Afficher les 5 premières lignes

head -n 5 connexions.log

  • Sortie attendue :

    2026-09-10 08:01:12 user=alice ip=192.168.1.10 status=SUCCESS
2026-09-10 08:02:45 user=bob ip=192.168.1.15 status=FAILED
2026-09-10 08:05:01 user=charlie ip=192.168.1.20 status=SUCCESS
2026-09-10 08:12:33 user=bob ip=192.168.1.15 status=FAILED
2026-09-10 08:14:10 user=alice ip=192.168.1.10 status=SUCCESS

  • Complément : Rappeler que la commande symétrique pour la fin de fichier est tail -n 5 connexions.log.

6.0.2 Question 2 : Filtrer les échecs de connexion

grep "status=FAILED" connexions.log
# ou simplement :
grep "FAILED" connexions.log
  • Explication : grep parcourt le fichier ligne par ligne et n’imprime sur la sortie standard que celles qui contiennent le motif textuel exact.

6.0.3 Question 3 : Compter le nombre total d’échecs en une ligne

grep "FAILED" connexions.log | wc -l
  • Résultat numérique affiché : 6
  • Mécanisme du pipe | :
    1. grep "FAILED" écrit les 6 lignes trouvées dans son flux stdout.
    2. Le tube | intercepte ce flux et le branche directement sur le stdin de la commande wc -l.
    3. wc -l (word count lines) compte le nombre de sauts de ligne reçus et affiche 6.
  • Variante native : grep -c "FAILED" connexions.log produit directement le même décompte sans tube.

6.0.4 Question 4 : Redirection vers un nouveau fichier

grep "user=alice" connexions.log > rapport_alice.txt

  • Vérification :

    cat rapport_alice.txt

    Le fichier contient les 3 lignes associées aux connexions d’Alice.

  • Point pédagogique : Insister sur la différence critique entre > (qui détruit le fichier de destination s’il existait déjà avant d’écrire) et >> (qui concatène à la fin).

6.0.5 Question 5 : Pipeline complet d’analyse décisionnelle

On cherche à produire la distribution des échecs d’authentification par utilisateur.

grep "FAILED" connexions.log | cut -d " " -f 3 | sort | uniq -c

  • Sortie exacte obtenue :

          3 user=bob
      2 user=eve
      1 user=mallory

  • Décomposition pas-à-pas du pipeline :

    1. grep "FAILED" : sélectionne uniquement les 6 lignes d’échec.
    2. cut -d " " -f 3 : découpe chaque ligne selon l’espace (-d " ") et extrait le 3e champ (-f 3), c’est-à-dire user=....
    3. sort : trie les chaînes par ordre alphabétique (user=bob, user=bob, user=bob, user=eve, user=eve, user=mallory).
    4. uniq -c : regroupe les occurrences identiques adjacentes et affiche leur effectif.

  • Piège capital à expliciter : La commande uniq ne compare que les lignes consécutives. Si l’on oublie sort, uniq -c ne regroupera pas les occurrences dispersées dans le fichier. Le passage par sort avant uniq est obligatoire sous Unix.

7 Le Défi Récapitulatif : Recherche Opérationnelle

Positionnement initial :

cd ../../defi

7.0.1 La solution canonique en une seule commande :

grep -r "INDICE_FINAL" serveurs/

  • Sortie immédiate :

    serveurs/beta/proc_7.log:2026-09-10 host=beta pid=1007 ALERT INDICE_FINAL : [LINUX_MASTER_2026]

7.0.2 Réponses attendues :

  1. Serveur concerné : serveur beta
  2. Fichier exact : serveurs/beta/proc_7.log
  3. Valeur de l’empreinte : LINUX_MASTER_2026

7.0.3 Variante alternative combinant find et xargs :

find serveurs/ -type f -name "*.log" -exec grep -H "INDICE_FINAL" {} +
  • Point pédagogique : L’option -r (ou -R) de grep permet une recherche récursive ultra-rapide dans tous les sous-dossiers. C’est l’équivalent textuel instantané de Ctrl+Shift+F dans un IDE moderne.

8 Pour Aller Plus Loin : Solutions des Défis Avancés

8.0.1 Défi A : Extraction de la liste unique des adresses IP

Solution 1 (Découpage syntaxique pur avec cut) :

cut -d " " -f 4 connexions.log | cut -d "=" -f 2 | sort -u

Solution 2 (Puissance des Expressions Régulières avec grep -oE) :

grep -oE "([0-9]{1,3}\.){3}[0-9]{1,3}" connexions.log | sort -u

  • Sortie ordonnée :

    10.0.0.99
172.16.0.4
192.168.1.10
192.168.1.15
192.168.1.20
192.168.1.35

  • Explication technique : L’option -o (only-matching) de grep n’affiche que la sous-chaîne qui correspond au motif regex, et non toute la ligne. L’option -u de sort applique le filtre d’unicité directement sans nécessiter uniq.

8.0.2 Défi B : Création de masse en une ligne (One-liner)

Solution optimale (Expansion d’accolades Bash) :

mkdir -p experience_{01..10} && touch experience_{01..10}/resultat.dat

Solution itérative classique (Boucle for) :

for i in $(seq -w 1 10); do mkdir -p "experience_$i" && touch "experience_$i/resultat.dat"; done
  • Point pédagogique : Montrer la puissance du mécanisme d’expansion native de Bash {01..10} qui évite d’écrire des scripts complexes pour instancier des plans d’expériences numériques.

8.0.3 Défi C : Traitement de flux structuré avec awk

awk -F'[ =]' '$9=="SUCCESS" { print "Utilisateur [" $6 "] connecté depuis l'\''IP [" $8 "]" }' connexions.log
  • Variante avec délimiteur par défaut :
awk '$5=="status=SUCCESS" {
    split($3, u, "=");
    split($4, ip, "=");
    print "Utilisateur [" u[2] "] connecté depuis l'\''IP [" ip[2] "]"
}' connexions.log

  • Sortie générée :

    Utilisateur [alice] connecté depuis l'IP [192.168.1.10]
Utilisateur [charlie] connecté depuis l'IP [192.168.1.20]
Utilisateur [alice] connecté depuis l'IP [192.168.1.10]
Utilisateur [charlie] connecté depuis l'IP [192.168.1.20]
Utilisateur [david] connecté depuis l'IP [192.168.1.35]
Utilisateur [alice] connecté depuis l'IP [192.168.1.10]
Utilisateur [bob] connecté depuis l'IP [192.168.1.15]
Utilisateur [david] connecté depuis l'IP [192.168.1.35]

  • Explication technique : L’option -F'[ =]' indique à awk que l’espace ET le signe égal servent simultanément de séparateurs de colonnes. La colonne $6 récupère directement la valeur du nom d’utilisateur et $8 l’adresse IP.
